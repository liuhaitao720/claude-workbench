# v2.2.3 发布说明

SSH Workbench v2.2.3 —— 修复：VM 重启后每次连接都被要求重新安装 cwb-server；
现自动拉起已装版本（零上传零解压）。cwb-server 保持 0.2.2。

## 1. 现象与根因

**现象**：每次重启服务端 Ubuntu（VM）并关闭客户端后，再次连接都弹出
「需要安装 cwb-server」确认窗，确认后走全量上传重装（1.7MB tgz）。

**根因**：cwb-server 由安装时 `nohup` 拉起，**不随 VM 开机自启**——重启后
进程消失、17717 无监听。客户端连接链的判定是「SSH 隧道已通而 WS 拒连 =
未安装」（`[cwb:need-server-install]` token → 安装弹窗），把「装了没跑」
误判成「没装」。

## 2. 修复：连接时自动拉起已装 server

WS 不通先做一次自动拉起，成功即重连，不弹任何窗：

1. 读远端 `~/.cwb-server/current` 指针 + 校验 `versions/<v>/dist/main.cjs`
   存在；
2. 存在 → `nohup` 启动该版本（与安装同一命令形态）+ 健康探活轮询；
3. 探活通过 → 重试 WS 连接（一次），恢复全部远程功能；
4. **零上传零解压**——纯启动既有安装产物；拉起日志进 server 日志面板
   （`[auto-start]` 前缀）。

并发路径（连接 + 重连对账同时触发）共享同一次拉起结果，不会双起进程。

## 3. 边界

- **真未安装**（current 指针/版本目录缺失）→ 照旧弹安装确认窗，语义不变；
- **拉起失败**（node 不可解析/启动秒退/探活超时）→ 原错误上抛 + 诊断
  （node 路径/pid 存活/server.log 尾部，ABI 不匹配给 rebuild 指引），
  可在弹窗里走完整重装兜底；
- 旧装配（未注入回调的测试替身）行为逐字节不变；
- 修复纯客户端侧，**cwb-server 无需升级**（保持 0.2.2）。

## 4. 验收建议

VM 里 `sudo reboot` → 客户端重连：应看到 server 日志出现
`[auto-start] starting installed cwb-server …`，随后直接连上、任务列表
恢复——**不出现安装弹窗**。
