# v2.1.6 发布说明（含 Windows 免安装包）

SSH Workbench v2.1.6 —— 修复：SSH 终端 cd 后文件面板从不跟随。

## 同版本号追加的三项完善（版本号不变；重新打包后生效）

- **连接管理按目录（分组）整理**：连接档案新增「分组」字段（设置「远程连接」表单与 SSH 视图纯 SSH 对话框均可填，datalist 复用既有分组）；SSH 视图列表按分组分节（📁 组名 ×N，名称序在前、未分组垫底），行内 SSH/DEV 徽标自说明；搜索匹配分组名
- **SSH 终端每台独立 tab**：每个开着的连接一个「▣ SSH 连接名」tab——点击互切不重开 shell，× 只关该台（关当前台自动切剩余台，全关退出视图）
- **任务 tab 标题=项目名-任务名**（项目缺失回落任务名）

## 症状与根因（两层）

终端里 `cd` 换了目录，下方文件面板一动不动。

1. **OSC 7 载荷解析一直是错的**：跟随靠 shell 每次提示符前回报 `OSC 7 ;
   file://host/path`，xterm 传给处理器的 data 就是 `file://host/path` 本身，
   而旧代码却做 `split(';')[1]` 取「第二段」——永远取到 `undefined` → 空路径
   → **从不导航**。（此前相关测试能过，纯属「显式定位先行写了同一路径」，
   没有真正走到解析。）
2. **v2.1.5 把跟随钩子也免了**：上一版按「裸进 SSH 视图不注入脚本」收紧时，
   把只报告 cwd 的 `PROMPT_COMMAND` 钩子也一并免掉了——钩子没了，面板更无从跟随。

## 修法

- OSC 载荷按 URL 直接解析（`file://host/path` → pathname）
- **跟随钩子每次开台都装**：`PROMPT_COMMAND` 只在提示符前回报当前目录，
  **不改目录**；`cd` 仍然只在「从任务窗口/项目上下文定向打开」时注入
  （v2.1.5 的指令不变：裸进不注入任何改目录的脚本）

## 跟随语义（按你的要求）

- 默认：终端 `cd` → 文件面板自动进入对应目录
- 面板手动切换目录后：
  - 终端没动（OSC 回报还是原目录）→ 不把面板拽回
  - 终端**再次 cd（目录真的变了）→ 直接跟到新目录**

工具栏「跟随目录」勾选仍是总开关；提示文案已更新为新语义。
