# v2.2.2 发布说明

SSH Workbench v2.2.2 —— 推送策略整治（在场门控 + 显式停止/退出全静默）+ cwb-server 0.2.2。

> 背景：v2.2.0 上线推送补全后实测反馈——人在电脑前与任务交互时，每一轮回复
> 结束手机都被「本轮完成」震动；关窗/菜单停止、退出应用也各有一串推送。
> 本版按用户裁决统一收敛：**手机通知 = 人不在场时的眼睛**。

## 1. 全部推送按「桌面在场」门控

**判定**：任一在线客户端 `presenceMin` 分钟（默认 5，设置页可调）内有键入
= 在场；无客户端在线（人走/应用关闭）或超窗未键入 = 不在场。

**行为**：在场时等待/完成/异常/退出**全部静默**；不在场才按事件开关推送。
本地与远程两侧对称门控（客户端 `AnswerBridge.desktopAway` / server
`desktopAway`）。手动「测试推送」不经门控（设置页按钮验证配置用）。

**实测定位**：「子 agent 还在推送」实测为零——子 agent 完成不触发任何推送
（SubagentStop 不订阅且两侧守卫）；所观察到的推送全部是主轮次 Stop 在
在场状态下照推，本项即其修复。

## 2. 显式停止一律不推

- **关任务窗口（tab ×）**：引发的「已停止」静默——`StopTaskOptions.quiet`
  贯穿契约 → markStatus → `task.kill` 帧（断连暂存补发也保留 quiet 标记），
  server 侧 `quietStop` 分流。
- **任务菜单「停止」**：同 quiet。
- **手机应答页停止**：同 quiet——应答页自身即有停止反馈，推送是重复打扰。

旧版客户端发出的无 quiet `task.kill` 仍走原「已停止」路径（升级兼容）。

## 3. 退出应用不推、停机不补推

- **退出应用**：before-quit 杀本地任务树引发的每任务「已退出」全部静默
  （`ctx.markQuitting()` 先于杀树置位）。
- **退出/停机不再补推**：原 10 秒合并窗内未推的「完成」会在退出前补推
  （flush），现改为直接丢弃（两侧 `dispose()`），与「人在场动作不推」语义
  一致。

## 4. 事件开关语义更新

「退出」开关现仅管进程**自行退出**（含异常退出）；显式停止与退出应用已由
本版钉死为永不推送。设置页提示文案同步（中英）。

## 5. cwb-server 0.1.x/0.2.1 → 0.2.2

- `task.kill` 帧新增 `quiet` 字段（关窗/显式停止静默）
- 手机 `/api/stop` 停止远程任务改静默
- hook 路由与任务退出回调挂**在场门控**（`desktopAway`，复用 presence 基建）
- 停机丢弃合并窗内的完成推送（不补推）
- 客户端首连自动比对 manifest 版本滚动升级，无需手动装
