# v2.1.5 发布说明（含 Windows 免安装包）

SSH Workbench v2.1.5 —— 三项实测定向修复：

- SSH 终端 bootstrap 注入**整行不执行**（引号未闭合，界面卡在 `>` 续行）——根治
- SSH 终端**每连接一台**：切换不同 SSH 连接=不同窗口，切回原样恢复（会话/回滚都在）
- **注入只服务定向打开**：不是从开发窗口/项目上下文进来的，就不往 shell 写脚本

## 修复：注入整行不执行（截图即 `cd '...'; export PROMPT_COMMAND=printf '\''\033]7;...` 后跟 `>`）

根因是 v2.1.3 注入文本里的单引号转义用错上下文：`'` → `'\''` 这种写法**只在已经在
单引号串内部时**成立，而当时把整段 `export PROMPT_COMMAND=printf '...'` 一并过了转义
函数，落在非引号上下文 → bash 认为引号未闭合，停在 `>` 续行提示符等后续输入，`cd` 与
OSC 7 钩子都不执行（所以也「没有进入任务所在的项目目录」）。

修法：

- hook 整体用单引号包裹，内部 printf 格式串改用双引号（printf 同样解析 `\033`/`\007`）——整行再无嵌套单引号
- 只剩 `cd '<目录>'` 一处需要转义，且它确实处在单引号串内
- 重试轮第一步改发 Ctrl+C，顺带脱困于残留的续行/半行输入
- 注入行已用 `bash -n` + 非交互实跑校验：`cd` 生效、eval `PROMPT_COMMAND` 输出 OSC 7 原始 ESC/BEL 字节

## 新行为一：每连接一台（用户需求）

此前切换连接会关掉旧 shell 并销毁终端，切回只剩空屏。现在：

- 每个开过的连接各有一块**常驻终端台**，非当前台仅隐藏（布局尺寸与回滚全保留）
- 下拉/侧栏切换即原样恢复，**会话不死**
- 死态按连接记：后台台断了只影响它自己，切回显示冻结层「重开会话」
- 关台（TabBar ×）或删除连接才真正断开并回收

## 新行为二：注入只服务「定向打开」（用户指令）

- 从任务窗口/项目上下文（带目录）打开 SSH 终端 → 注入 `cd` + OSC 7 钩子（文件面板直达项目目录、目录跟随可用）
- 从竖条或 Ctrl+Shift+S 裸进 SSH 视图 → **不往 shell 里写任何脚本**（目录跟随改由你自己 shell 的 OSC 7 决定）

## 安装

Windows 覆盖安装：`SSH-Workbench-Setup-2.1.5.exe`（配置保留）。

**免安装版**：`SSH-Workbench-2.1.5-win-portable.zip`——解压到任意目录，双击
`SSH Workbench.exe` 直接运行；与安装版共用同一配置目录（%APPDATA%\SSH Workbench），
二者不要同时运行。
